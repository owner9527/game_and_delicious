# 十款游戏「美术与场景」优化 · 统一施工规范

> 本文件是给每一位负责单款游戏的执行者的统一规范。请先读完，再动手。

## 0. 总目标

用户原话：**「把文件夹下的十个游戏都进行优化，美术和场景方面都要优化，不能只要像素块」**

翻译成可验收的标准：

1. **不能再是大色块 / 像素块**。地面、墙体、天空、水面、UI 面板等大面积区域，必须摆脱"纯色矩形"观感。
2. **要有场景氛围**：天空渐变、地平线、远景层次、地面纹理、光照与阴影、雾/暗角/辉光、粒子浮尘。
3. **要有细节与质感**：材质差异（石 / 木 / 金属 / 玻璃 / 水 / 草 / 沙）、边缘高光、接触阴影、环境遮蔽感。
4. **UI 也要好看**：面板用渐变 + 内高光 + 边框光 + 柔和投影，不要平面色块；标题有层次；按钮有状态反馈。
5. **玩法不能坏**。所有改动只允许发生在"表现层"，不得改变游戏规则、数值、关卡数据、存档格式、输入语义。

## 1. 硬性约束

- **零外部资源**：这些游戏都是"零依赖、零素材、双击即玩"。**禁止**引入图片/字体/音效文件、CDN、npm 包。所有美术必须用 Canvas 2D 绘制代码、CSS 或内联 SVG 程序化生成。
- **必须能离线 `file://` 打开**：不要改用 ES module / `fetch` 加载本地资源。
- **性能**：目标 60fps。禁止每帧对全屏尺寸的 `ImageData` 做逐像素运算。噪声/纹理请：
  - 预生成一张小的离屏 canvas（如 128×128 或 256×256）并 `createPattern` 平铺；或
  - 只在初始化时算一次并缓存；或
  - 用低分辨率离屏层（如 1/3 尺寸）再放大绘制。
- **不得删改存档 / 关卡 / 数值逻辑**。修改前先想清楚这段代码是否只负责"画"。
- **保留中文注释风格**，新增代码写简短中文注释说明意图。
- 不要重构整个文件，不要改文件结构。**外科手术式修改**，集中在渲染函数里。

## 2. 每款游戏的通用"加分清单"

按适用性挑选（不是每条都必须）：

- [ ] **天空/背景**：3 段以上渐变（天顶→地平线→地面辉光），加一层缓慢移动的云/雾带（用低透明度多层噪声图形）。
- [ ] **远景层次**：至少 2 层远山/建筑剪影，越远越淡越偏冷色（大气透视）。
- [ ] **地形纹理**：地面不写单一 `fillStyle` 纯色，而是"基色 + 噪点 pattern + 若干明暗斑块 + 边缘过渡"。
- [ ] **自动描边/细节**：给地块加不规则边缘（手绘感），而不是完美矩形。
- [ ] **光照**：主光源方向统一（如左上），物件加**接触阴影**（脚下椭圆软阴影）+ **受光面高光**。
- [ ] **发光**：火把/灯/晶体/传送门等用 `createRadialGradient` 做光晕，叠加 `lighter` 混合。
- [ ] **粒子**：尘埃、火星、萤火、落叶、水汽——每类 20~80 个，带生命周期与透明度衰减。
- [ ] **水面**：多层正弦波 + 高光条 + 倒影色，不要纯蓝矩形。
- [ ] **后处理**：屏幕暗角（vignette）、轻微的色调映射/色彩分级，让整体像"一个场景"而非拼贴。
- [ ] **UI**：面板 `linear-gradient` + `inset` 内高光 + 1px 亮边 + 柔和外阴影；重要数值用对比色；进度条用渐变填充 + 高光。
- [ ] **标题/菜单**：渐变文字、字间距、入场动画、背景有缓慢流动的光。
- [ ] **过渡动画**：关卡切换 / 场景切换加淡入淡出或推镜，不要硬切。

## 3. 禁止事项

- ❌ 只把颜色调亮一点就交差。
- ❌ 用同一个 `fillStyle` 画几十个矩形。
- ❌ 用 `ctx.font` 里塞 emoji 冒充美术。
- ❌ 引入外部图片。
- ❌ 让帧率明显下降（改完必须实测）。
- ❌ 改动玩法/数值/存档。
