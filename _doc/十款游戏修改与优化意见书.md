## 一、这份文档是什么

这份意见书针对 `D:\游戏` 目录下的十款自研网页游戏，逐款给出**可执行的修改与优化建议**。它不是在赞美现状，也不是泛泛而谈"要提升体验"，而是尽量回答三个问题：**现在哪里不好、为什么会这样、具体怎么改**。

需要先声明这份文档的**证据基础**，以免读者误判可信度：

| 证据类型 | 说明 |
|---|---|
| **实测证据** | 本轮与上一轮迭代中，我用 headless Edge + CDP 真实加载过每一款游戏，抓取过 console 报错、页面异常、元素坐标、帧率、以及游戏内部状态（通过 `--eval` 注入断言读取 `G`/`SF` 等运行时对象）。文中"实测"字样均指这类证据 |
| **代码证据** | 阅读过各款游戏的核心源码，文中指出的根因大多能对应到具体文件与函数 |
| **推断建议** | 优化建议本身属于"我认为这样做会更好"，其中一部分基于同类游戏的设计惯例，**并未经过玩家验证**。这类内容我会明确写成"建议"，而不是"必须" |

不在这份文档里的内容：**没有做过真实玩家测试**，没有留存率/时长等数据，也没有做过付费或商业化分析。所有关于"玩家会怎样"的判断都是基于设计逻辑的推断。

## 二、总体评价

### 2.1 共同的技术底座（这是十款游戏最大的优势）

十款游戏共享一套非常克制的技术选择，值得先说清楚，因为**后面所有优化建议都必须在这个前提下讨论**：

- **零依赖、零素材**：没有 CDN、没有 npm 包、没有图片/音频文件、没有 ES module、没有 `fetch`。所有美术都是 Canvas/CSS/SVG 程序化生成。
- **`file://` 双击可玩**：十款全部实测过，直接双击本地 HTML 就能跑，唯一代价是 `file://` 下 `localStorage` 在部分浏览器受限（有游戏已做 `try/catch` 兜底）。这意味着**分发成本几乎为零**——发给别人一个文件夹就能玩。
- **存档在浏览器本地**：各用各的 localStorage key，互不冲突。
- **性能余量充足**：在带 GPU 的真实浏览器里，实测《星火拓荒》191fps、《星穹拓荒》167fps，远超 60fps 目标。

这套底座的代价也很明确：**没有构建工具链**，所以代码组织是"多文件挂全局变量"（`G`、`SF`、`MMGame` 这类），单文件体积偏大（最大的 `8/js/ui.js` 约 91KB、`3/js/render.js` 约 105KB）。这在"改一处不影响别处"上是加分，在"新人接手"和"回归测试"上是减分。

## 三、逐款修改与优化建议

### 3.1 01 余烬之城 · 多结局剧情冒险


**现状**
单文件 176KB 的纯前端多结局文字冒险：49 个节点键（39 个剧情节点 + 10 个结局）、5 章、正文约 5,300 字。`REG` / `STORY` / `ART` / `LOGIC` 四段分离得很干净——扩剧情只需往 `STORY.nodes` 加一条。已有结局图鉴（未解锁显示提示）、localStorage 自动存档、背包 / 手记 / 设置 / 说明、键盘 1~9 选支，以及 17 个程序化矢量场景、16 套主题与 WebAudio 实时配乐。完成度在本合集里属于上游，源码里还写满了性能取舍的注释。

**主要问题**
1. **道德被锁死为非负，堕落线是死代码**：`applySet` 对所有变量做 `Math.max(0,…)`，导致 `f_fate` 里 `moral:"<=-3"` 的第 5 条路线**恒不成立**（实测 `applySet({moral:-5})` 后 `moral` 仍为 0）。更糟的是 `updateHUD` 在值为 0 时把 chip 设为 `none` 并 `return`，于是 9 个负道德选项（如 `s_shop -2`、`h_ward -3`）玩家**看不到任何反馈**。
2. **手机上对话框会跑到屏幕外**：`#dialog` 只锚 `bottom` 且没有高度上限，`#dlgBox` 又是 `overflow:hidden`。实测 360×640 打开 5 选项的 `f_seats` 时，`dlgBox` 顶部为 **-159px**、正文被裁且不可滚动；4 选项的 `h_front` 与 103px 高的 HUD 重叠。
3. **章节卡只有 click 一条路**：`showChapterCard` 只给 `#chapCard` 绑了 `click`，实测空格 / 回车 / Esc 都无法关闭，而此刻 `#dialog` 是 `display:none`——**纯键盘玩家在 5 张章节卡上必卡死**。全站 25 个可点控件都是 `span`/`div`，`tabindex`/`role` 数量实测为 0。
4. **每次节点跳转都黑场重绘**：`swapArt` 无条件 `setTimeout(…)120` + `.swapping{opacity:0}`，而 39 个节点只对应 17 个场景（metro 占 8 个、lab 占 6 个），大量同场景切换都在空转，每次都重新 `innerHTML` 解析约 50KB、556 个 SVG 元素（含 58 处滤镜引用）。
5. **存档只有一个自动槽**：单键 `SAVE_KEY`，无手动存读、无章节选择、无回退，`doEnding` 还执行 `clearSave()`——想换结局只能从 5,300 字开头重玩。且 `saveGame()` 的 `catch(e){}` 会**静默吞掉隐私模式下的写入失败**。
6. **AVG 标配缺一批**：没有对话历史回看（"手记"只存节点正文、不记你选了哪一项，实测 log 条目无 `choice` 字段）、没有已读快进、没有自动播放、没有字号 / 音效独立开关 / 全屏 / 减少动效。另外 `sfx()` 与 `sting()` 都被 `musicOn` 卡住，**关掉 BGM 会连音效一起静音**。

**优化建议**

- **P0｜放开道德下限**：按 `REG.vars[k].min` 取值（moral 设 -10、其余 0），并让 moral / supplies 常驻显示、`d<0` 也走浮动提示。**为什么**：这是让 E07 的两条路线真正可用、让"做坏事立刻有负反馈"的前提，道德从"只能上涨"变回双向。
- **P0｜对话框加高度上限与滚动**：`#dialog{max-height:calc(100dvh - 110px)}`、`#dlgBox{max-height:100%;overflow-y:auto}`，选项区补 `padding-bottom:env(safe-area-inset-bottom)`，并把误写在 `#dlgBox` 上的 `bottom:12px` 移回 `#dialog`。**为什么**：小屏与大字号下正文不再被裁到屏幕外。
- **P0｜章节卡与弹层补键盘可达**：`#chapCard` 加 `keydown`（空格 / 回车 / Esc 关闭）；`.tbtn/.hbtn/.opt/.seg span` 改为 `<button>` 或补 `role="button" tabindex="0"` 并支持 Enter/Space 触发；加 `:focus-visible` 样式，toast 加 `aria-live`。**为什么**：说明页承诺了"键盘也能玩"，而现在键盘玩家会在章节卡卡死。
- **P0｜场景缓存 + 免黑场切换**：`swapArt` 先比对新旧 scene，相同则 `return` 或只换种子；不同时按 sceneKey 缓存 `ART.render` 结果，用双层交叉淡入替代 120ms 黑场；顺带去掉 `#stage::after` 的 `mix-blend-mode:overlay`、小屏关掉 `#dlgBox` 的 `backdrop-filter:blur(8px)`。**为什么**：每步点击不再闪黑，弱机上少一次 50KB SVG 解析与每帧重算模糊。
- **P1｜多存档槽 + 手动存读 + 导入导出**：`SAVE_KEY` 扩成 3 槽数组（node/vars/items/visited/log/chapter/ts），标题页加「读取存档」，设置里加导出 / 导入（base64 JSON）；写入失败改为 toast 报错；把已存却没展示的 `save.ts` 显示到「继续旅程」上。**为什么**：换路线、换设备、清缓存不再等于从零开始。
- **P1｜决策快照 + 岔路口重开**：`saveGame()` 时把最近 3 次 `(node, 选项序号, 选项文本)` 压进 `state.trail`，结局页加「从这个岔路口重开」，按快照恢复后 `enter(node)`。**为什么**：收集 10 个结局不必每次重读全文，这是多结局游戏最关键的一个功能。
- **P1｜补对话历史（backlog）**：对话框加「↺ 回看」，面板按节点缓存 `resolveText` 结果并追加「你选择了：…」，在选项点击处写 `state.log.push({t,x,choice:op.text})`。**为什么**：现在的手记看不到自己选过什么，而"我刚才选了什么"是分支叙事的刚需。
- **P1｜已读快进 + 自动播放**：用 `state.visited[id]` 判定已读，已读节点打字速度临时按 0；对话框右上角加「▶▶ 快进」与「AUTO」。**为什么**：这是刷图鉴的必要工具，现在只有全局"瞬间"挡位。
- **P1｜设置补齐 + 音频修正**：新增字号三档（`#dlgText` 的 `clamp` 换成 `--fs`）、音效独立开关与音量（`sfx`/`sting` 改看 `settings.sfx` 并走独立 `sfxGain`）、「减少动态效果」（或响应 `prefers-reduced-motion`）、全屏。并修 `AudioSys`：`play()` 在首次手势时因 `cur` 已等于曲名而直接 `return`（音乐实际靠 `sfx()` 的 `resume` 才启动），`tick()` 的 `while` 还会把挂起期错过的小节全堆进 1.4 秒。**为什么**：关 BGM 仍有音效，弱机与眩晕敏感用户都能调。
- **P1｜图鉴可点开 + 差什么一目了然**：图鉴卡片现在是死 `div`、只显示第一段前 40 字，改为点击展开结局全文；给 `STORY.endings[eid]` 补 `cond` 字段，结局页显示「条件：血清 + 知晓真相 + 道德≥5 + 好感≥6（你满足 3/4）」。**为什么**：真结局不再只靠"线索藏在故事里"一句空话。
- **P2｜变量显性化与新手指引**：让道德 / 物资 / 三位同伴常驻 HUD（现在全为 0 时整条只剩物资），某变量首次变动时 toast「新增变量：小满好感」；在 `s_shop` 这类节点先给一句「🔒 需要步枪子弹」的获取提示。**为什么**：玩家目前看不出存在隐藏变量，也看不懂锁住的选项从哪来。
- **P2｜场景差异化与文本量**：metro 一个场景承担 8 个节点，建议给高频场景加 2~3 个构图 variant；`ART.render` 的 `seedStr` 现用 `state.node`，同一地点每个节点构图都在跳，改为 `chapter+scene` 稳定下来才像同一个房间；终章 10 个结局的铺垫与正文也值得再扩。**为什么**：现状既削弱了空间感，单周目体量也偏小。

**这条最值得先做**：道德下限与"岔路口重开"。前者是修一个**已经写好却永远走不到的分支**（等于白做了一整条剧情线），后者决定玩家愿不愿意去收集 10 个结局。

### 3.2 02 星火拓荒 · 无尽之地


**现状**
纯原生 Canvas 2D 生存建造游戏，10 个 JS 模块约 195KB，零依赖零素材。完成度很高：16×16 分块的无限大陆、9 种资源、13 种建筑、8 项科技、昼夜 / 下雨 / 随机事件 / 蚀影兽夜袭、工人与无人机 AI、脏块差分存档都在跑；右键快捷建造、B/T/H 快捷键、5 页指南齐全。**渲染层（预烘焙贴图、明暗×色相二维色板、光影遮罩、环境粒子）与数据驱动层是本合集里的亮点**；实测地形生成 0.08ms/块、新建存档仅 2KB。

**主要问题**
1. **手机端零触控**：`main.js` 只绑鼠标事件，快捷建造菜单只在 `e.button === 2` 的 `mouseup` 里打开（`main.js:310`）——触屏没有右键，于是**建造 / 框选 / 取消三条主线全断**。
2. **仓储满仓会静默饿死**：仓储是全局总上限（`Pool.add` 按 `cap() − total()` 卡总量，`buildings.js:25`），满仓时**任何物品都进不去**；厨房产出的面包卡在建筑自己的 `buf.out` 里，而 `Pool.eat` 只读 `G.pool`（`buildings.js:43`）——**满仓即食物断供**，20 秒模拟里 0 条提示。
3. **存档单槽，且"采空区块"不落盘**：`save.js:27` 会跳过 `nodes.size === 0` 的脏块，实测**采空的块读档后会重新长出 93 个资源节点** → F5/F9 可以无限刷资源。
4. **蓝图不可取消**：`place()` 先扣费，之后点蓝图只会让玩家去锤（`actors.js:141`），拆除按钮只存在于"已建成建筑"的详情面板里。
5. **打开面板不暂停，首个夜晚来得太快**：打开科技树/指南时 `Systems.update` 照跑（实测 `pausedWithTechOpen = false`）；开局 `dayFrac = 0.32`（`main.js:53`），约 100 秒后就迎来第一波夜袭（`systems.js:56`）。
6. **信息与指挥层缺失**：科技树无搜索无队列（8 项共 1455 科研点）、没有工人名单/血量/任务、小地图固定 82×82 格且不可点（`render.js:2056`）、相机**永久跟随玩家**（`render.js:443`）、天黑只有一条日志加音效。

**优化建议**

- **P0｜补触控层，把右键的三件事搬上触屏**：长按弹出快捷建造菜单、单指点按采集/落点、加一个「标记模式」按钮替代框选；同时给 canvas 加 `touch-action:none` 并按 `devicePixelRatio` 缩放（`render.js:65` 现在直接用 `innerWidth`，高 DPI 屏会发糊）。**为什么**：现在手机上**完全无法建造**，而且没有任何长按之类的替代入口。
- **P0｜仓储溢出保护**：给食物与关键物资留保底格位（例如 20% 容量只收食物），或满仓时按优先级替换；满仓必须 `UI.msgFull` 播报「仓储已满，X 已停产」；并允许玩家与工人直接吃建筑 `buf.out` 里的食物。**为什么**：**"满仓静默饿死"是致命且无从察觉的失败**——玩家会觉得游戏坏了。
- **P0｜修存档并扩成多槽**：`serialize()` 改判 `ch.dirty`，把采空块写成空节点表（或标 `empty:true`）以免读档复活；加 3 个槽位与 `visibilitychange`/`beforeunload` 自动保存。**为什么**：既杜绝读档刷资源，也让"关掉页面不丢档"成立。
- **P0｜蓝图可取消 + 批量建造**：点击蓝图即取消并**全额退款**；右键拖拽沿直线批量下蓝图并按仓储余量截断；保留 Shift 连续放置。**为什么**：误放的代价现在太高，而围墙/仓储只能一格一格点。
- **P1｜面板暂停 + 夜间预警 + 小地图交互**：开面板时把 `dt` 归零（或 ×0.1）；时钟旁显示「距天黑 mm:ss」，夜袭前 20 秒 HUD 闪红并给屏幕边缘方向箭头；小地图可点击跳转/缩放，标出工人（蓝）、已标记资源（白）与火光范围。**为什么**：现在"看面板等于送死"、天黑毫无准备、小地图只是装饰。
- **P1｜工人指挥与信息**：加工人列表（名字 / 血量 / 饥饿 / 当前任务 / 位置），点列表可指派其去指定格（临时 job 优先级 9），加「宵禁 / 回营」开关让工人入夜不外出；顺手修 `wFlee` 里"篝火旁回血"其实是无条件回血（`actors.js:470`）。**为什么**：工人是核心资产却是个黑箱。
- **P1｜科技与建造面板**：科技面板加研究队列（攒够自动解锁）与「全解锁还需约 x 分钟」的估算；建造面板补「缺什么」一键跳到资源标记；把 1455 点总成本下调 20%~30%，或把工作台 0.5 → 0.8 科研点/秒。**为什么**：中后期现在几乎是纯挂机等科研点。
- **P1｜性能热路径**：`getLights()` 被 `nearLight` 逐怪重算（24 怪 × 2 = 48 次全量 `ECS.query` + 数组分配，而渲染层其实已缓存一份）→ 改为按帧缓存；`findPath` 的 open 表线性扫描（`O(n²)`，`maxExp 2600`，`world.js:164`）→ 换二叉堆并给工人分帧寻路；`Pool.cap()` 每次都 `countDone` 全量查询（`buildings.js:24`）→ 改计数器；光照遮罩 `lcv` 改半分辨率再放大。**为什么**：实测无 GPU 软件渲染下夜间遮罩 9.3ms/帧、压力场景（60 建筑 + 10 工人 + 24 怪）**106 → 23fps**，低端设备明显吃亏。
- **P2｜可访问性**：资源筹码补 1~2 字缩写与 `aria-label`（现在只有色点）、加色盲配色档、提供 100%/125% UI 缩放（字号固定在 10~11px）、音效开关持久化到 localStorage、支持键盘建造（方向键移光标 + Enter 落点、数字键选建筑）。**为什么**：画布内玩法**100% 依赖鼠标与颜色**。
- **P2｜资源再生与末局长线**：树木 / 浆果丛缓慢再生，或加"树苗"建筑；自动采矿机枯竭后自动寻找最近的同类矿脉；末局需要 100 铁锭 = 200 铁矿 + 100 煤，而采矿机产出仅 1 单位/8 秒。**为什么**：浆果丛不回头会让前期食物不可逆枯竭，末局又变成纯等待。

**这条最值得先做**：手机触控。它是这份意见书里**唯一一条"整款游戏在主流设备上完全不可玩"**的问题，而且改造面并不大——输入事件集中在 `bindInput` 一处。

### 3.3 03 拓城记 · 中古殖民模拟


**现状**
自顶向下网格经营的殖民地模拟，居民由「住房/食物/娱乐/医疗/信仰」五类需求驱动。本轮刚修掉四个真问题：资源不会再生、节奏过快、基建无产出、居民数量失控。现在有了可再生资源层（`js/resources.js` 的 `G.NAT`）、4 秒/天的节奏与 0/1/2/3 档速度、真正结算的森林加成与按需求比例分摊的用工、以及"一名居民对应一个行走单位"的收敛，居民可点选查看职业与当前任务。**它的美术层（23 种建筑独立剪影、不规则地块边界、云影与昼夜分级）在本轮之前就已做完，质量不错。**

**主要问题**
1. **生产链对玩家是黑箱**：虽然本轮让"有产出"变得可见（头顶浮字、顶栏涨跌、昨日产出表），但"谁供给谁、哪个环节卡住"仍然只能靠猜。玩家看到石料不涨，无法一眼判断是没矿、没人、还是仓储满了。
2. **目标链 11 个里程碑的存在感偏弱**：它是这款游戏真正的长线引导，但埋在面板里，玩家更容易陷入"看着城市运转但不知为何而玩"。
3. **季节与灾害缺少前瞻预警**：秋冬粮荒是设计核心（"秋冬囤粮是生存关键"），但玩家只在粮仓见底时才后知后觉。
4. **居民寻路的可读性**：本轮加了目的徽标，但大量居民同屏时仍然难以判断谁是"去上班"、谁是"在家"。
5. **存档只有单档**：一次误操作（比如拆错一片城区）没有退回余地。

**优化建议**

- **P1｜生产链透视面板**：在城市面板里加一行「本日生产 → 消耗 → 净变化」的流向表，把每类资源拆成"建筑产出 / 居民消耗 / 浪费"。**为什么**：这是经营类游戏最标准的可读性设施，做了之后"基建没收入"这类困惑会从根上消失。**怎么做**：`economy.tick` 已经记录了 `lastProd/lastWant/lastOverflow` 快照，直接聚合成表即可，不需要新增模拟逻辑。
- **P1｜把目标链顶到主界面**：在顶栏放一条常驻的「当前目标 + 进度」窄条（类似《星穹拓荒》的教学任务面板），点开才是完整 11 项列表。**为什么**：长线目标不显眼等于没有。
- **P1｜季节/灾害前瞻预警**：入秋时用横幅提示"距冬季 N 天，预计粮食缺口约 M"，并给出建议动作。**为什么**：把"事后惩罚"变成"事前规划"，是这类游戏体验差异最大的一个改动。
- **P1｜建筑信息面板补齐明细**：产出/维护/用工/周边资源蓄积/是否满负荷，一屏说清。**为什么**：玩家花金币建的建筑，必须能一眼看懂它现在干得好不好。
- **P2｜多存档槽位（3~5 个）+ 自动存档保留最近 N 份**：**为什么**：模拟经营玩家天然会"试错后想反悔"。
- **P2｜居民寻路可视化开关**：放大到一定倍数时显示"家→工作地"的连线。**为什么**：直接回应"这么多人跑来跑去到底在干嘛"。
- **P2｜暂停时允许规划**：暂停下建建筑、改分工。**为什么**：降低操作压力，也顺手解决"速度太快看不懂"的残余。
- **P2｜关键事件日志可回看**：把事件横幅收进一个可滚动的时间线。**为什么**：错过横幅的玩家不该永久失去信息。

**这条最值得先做**：生产链透视面板。它用已有的数据快照就能做出来，却能一次性解决"为什么没收入""资源去哪了""仓储是不是满了"三个高频困惑。

### 3.4 04 深渊词条 · 肉鸽打宝


**现状**
俯视角动作肉鸽。本轮修掉三处：**楼梯房没有可交互出口**（这是致命的——`makePickup('next')` 全项目只在击杀 Boss 分支出现，而第 1 层没有 Boss，理论上永远无法通过）、攻击手感呆滞（投射物只看当前帧落点导致掠射失效、点击无输入缓冲）、以及完全没有新手引导。修完后实测**连续通过 1→2→3→4 层**，按下到开火从 16.5ms 降到 0ms，并补了 9 步引导。第一轮还做过地牢美术（石板地面、伪 3D 墙体、1/4 分辨率光照层、后处理烘焙）。

**主要问题**
1. **"封印"机制虽然现在有提示，但仍可能让新玩家困惑**：锁定态提示是文字（"清空本房间敌人后开启"），但如果最后一个敌人卡在角落或玩家没看见，仍然会停顿。
2. **缺少"我这一局在往哪走"的全局感**：小地图与箭头已有，但没有整层的进度感（还剩几个房间、离 Boss 还有多远）。
3. **词条/装备缺少对比与保护**：肉鸽的乐趣在搭配，但玩家很难判断"新掉的这件是不是比身上好"，也容易误操作。
4. **掉落拾取需要手动逐个跑**：刷宝类游戏里，捡东西的时间占比过高会稀释爽感。
5. **移动端触控未明确**：这款依赖键盘（`KeyW/A/S/D` + 鼠标开火），手机上无法正常游玩。

**优化建议**

- **P1｜房间清空进度常驻显示**：在 HUD 上显示"本层进度 3/7 房间 · 剩余敌人 N"。**为什么**：直接消除"我是不是卡住了"的焦虑。**怎么做**：`enterRoom` 已经维护 `room.cleared`，聚合计数即可。
- **P1｜"最后一个敌人"高亮**：房间只剩 1 个敌人时，给它加描边并让镜头轻微提示。**为什么**：卡关 90% 的情况就是那一个漏网的怪。
- **P1｜装备对比浮层**：拾取时按住某键显示"与当前装备的数值差（+/-）"。**为什么**：这是刷宝类游戏的标配，缺失会让玩家干脆不捡。
- **P1｜移动端虚拟摇杆 + 开火按钮**：左下摇杆移动、右下按钮开火/冲刺。**为什么**：不做这一条，手机上这款游戏等于不存在。
- **P2｜磁吸拾取**：一定范围内的金币/消耗品自动吸附。**为什么**：把时间还给战斗。
- **P2｜本层小地图进度环**：小地图外圈画一圈房间进度。**为什么**：给玩家"快到了"的期待感。
- **P2｜Boss 层预告与准备房**：进 Boss 前给一个可以整理装备、补血的房间。**为什么**：突然进 Boss 房被打死是最挫败的体验。
- **P2｜伤害数字分级与暴击高亮**：让"这一下打得很重"可感知。**为什么**：手感的一半来自反馈而不只是帧数。

**这条最值得先做**：装备对比浮层。它把"捡不捡"这个高频决策从猜测变成比较，直接影响刷宝循环的爽感。

### 3.5 05 幻境争锋 · 战棋自走棋


**现状**
单文件自走棋。第一轮做了大幅美术升级（棋盘整块离屏烘焙、5 种地形材质、6 职业×6 种族英雄立绘替换全部 emoji、三层浮空岛视差背景、战斗演出），本轮补了 9 步聚光灯引导（买东西→备战席→拖上棋盘→调站位→羁绊→经济→开战）。实测引导期间 `pointer-events:none`，玩家照常买人、拖拽、开战。

**主要问题**
1. **阵容无法保存**：自走棋的核心乐趣是"研究出一套阵容再反复用"，每次从头摆非常消耗耐心。
2. **战斗过程"看不懂"**：战斗全自动，但玩家不知道谁打了多少伤害、这套阵容强在哪、输在哪。
3. **商店概率不透明**：不同等级的英雄出现概率是这类游戏的策略核心，隐藏它会让决策变成赌博。
4. **羁绊推荐缺失**：新手面对 23 个英雄 + 多套羁绊，不知道往哪个方向凑。
5. **触控拖拽在小屏上精度不足**：棋盘格子小，拖歪了就放错位。

**优化建议**

- **P1｜阵容预设（3~5 套）**：保存站位与英雄，一键套用。**为什么**：这是自走棋留住玩家的关键功能，没有它每局都在重复劳动。
- **P1｜战斗结算面板**：战斗后显示每个单位的伤害/承伤/治疗排行。**为什么**：把"自动战斗"从黑箱变成可分析对象，玩家才有优化动力。
- **P1｜商店概率公示**：在商店旁边显示"当前等级下各费卡出现概率"。**为什么**：这是策略深度的来源，藏着只会让玩家觉得随机。
- **P1｜羁绊推荐/高亮**：当玩家已凑到某羁绊 2/4 时，把能补齐的英雄在商店里高亮。**为什么**：新手最需要的就是"下一步买谁"。
- **P2｜战斗回放/倍速细化**：现在有加速，建议再加一次"逐回合"或"关键帧pause"。**为什么**：让人有机会看清那一波团战是怎么崩的。
- **P2｜触控吸附与放大镜**：拖拽时把目标格放大并吸附。**为什么**：直接解决小屏精度问题。
- **P2｜连续对局与局内成长记录**：记录最近 N 局的阵容与名次。**为什么**：给非排位玩家一个自查工具。
- **P2｜音效层次**：不同稀有度/羁绊激活给不同的听觉反馈。**为什么**：自走棋的爽感很大一部分来自"胡牌"的即时回馈。

**这条最值得先做**：阵容预设。它直接对应"每局重复劳动"这个最大的流失点。

### 3.6 06 回声 Echo · 声音解谜冒险


**现状**
这款是整个合集里**概念最锋利**的一款：玩家扮演失去视觉的"聆听者"，全程零文字，靠探测音、录音、回放、和弦叠加解开谜题。第一轮修掉了两个致命问题——隐藏主菜单用 `pointer-events:auto` 挡住了启动页导致**点「开始」毫无反应**，以及 `this.initFX is not a function` 导致**进关卡直接崩**。之后又做了游戏内美术升级（环境低频斑块、墙体辉光、声波多层光环、尘埃、后处理分级），并调低了整体亮度以免破坏"黑暗"的基调。

**主要问题**
1. **对听障用户完全不可用**：声音是唯一信息通道，而游戏里的"声纹可视化"虽然存在，但只是辅助，关键判定仍依赖听觉。
2. **对普通用户的理解成本极高**：零文字是设计美学，但玩家进入第一关后没有任何"我知道了"的时刻，很容易在 2 分钟内退出。
3. **长时间高频音可能造成听觉疲劳**：探测音与回声环是持续触发的。
4. **卡关时缺少渐进式帮助**：代码里有"卡住 180 秒出现箭头提示"的机制，但 3 分钟对一款 5 分钟一关的游戏来说太长。
5. **缺少关卡编辑器或沙盒创作**：这类机制天然适合让玩家造谜题。

**优化建议**

- **P0｜把"视觉化"提升为可选的一等公民**：在设置里提供"视觉辅助：关 / 基础 / 完整"三档，完整档把声音的全部属性（延迟→距离、音调→体积、音色→材质、左右→方位）用图形明确表达出来。**为什么**：这不只是无障碍——很多玩家在嘈杂环境（地铁、办公室）会静音玩游戏，视觉辅助决定了他们能不能玩。
- **P1｜首关做成"引导关"但保持零文字**：用图形/色调/节奏在 30 秒内教会"点一下会发声、声波会照亮东西"。**为什么**：概念型游戏必须在前 60 秒交付一次"啊哈"。**怎么做**：把现有 `l1` 拆成三个微型阶段，每阶段只引入一个新操作，用同一套声波视觉语言示范。
- **P1｜把提示时间从 180 秒降到 60 秒，并分级**：60 秒给一次轻微的方向色彩提示，120 秒给明确箭头。**为什么**：手机上玩家耐心更短。
- **P1｜响度与频率保护**：给探测音加一个渐入包络，并在设置里提供"温和模式"（限制峰值音量与高频能量）。**为什么**：长时间游玩不应该让人头疼。
- **P2｜关卡编辑器 + 分享码**：让玩家用同一套机制造谜题，用 URL/字符串分享。**为什么**：这类机制的自传播能力极强，而且几乎不增加服务器成本（分享码可以完全放在链接里）。
- **P2｜"听觉档案"**：把玩家收集到的声纹做成可回放的图鉴。**为什么**：给收集行为一个明确的落点。
- **P2｜节奏可调**：允许把回声延迟整体缩放（现在有"回声校准"滑杆，可以扩展成"难度"）。**为什么**：听感差异很大，硬编码的延迟对部分玩家就是噪声。

**这条最值得先做**：三档视觉辅助。它同时解决无障碍、静音场景、和理解成本三个问题，是这款游戏从"概念惊艳但玩不下去"变成"真的能玩"的关键一步。

### 3.7 07 镜像迷城 · Mirror Maze


**现状**
2.5D 横版对称光学解谜：双子（左·青）与长（右·橙）被真实之镜分隔，**一套输入同时驱动两个角色**。第一轮做了镜面/光束/场景/角色的美术升级（冷→暖镀膜渐变、5 层辉光光束、石砖与金属格栅材质），本轮补了**核心 8 步 + 机关 3 步**引导，聚光灯按世界坐标投影精确套在机关格子上（误差 ≤1px）。30 关全部通过校验器。

**主要问题**
1. **左右两侧靠颜色区分（青/橙）**：色盲玩家会失去最核心的方位线索。
2. **"一套输入驱动两人"是最大卖点也是最大门槛**：即使有引导，前几关仍可能让玩家手忙脚乱。
3. **缺少关卡筛选与进度总览**：30 关 + 星级，想回头补三星要逐个翻。
4. **提示系统的成本不透明**：用了提示会不会影响星级，玩家不清楚就不敢用。
5. **移动端虚拟摇杆与跳跃的手感**未经过专门调校。

**优化建议**

- **P0｜给左右两侧加形状/纹理冗余**：除了青/橙，再给左侧加"细纹/圆点"、右侧加"粗纹/斜纹"的角色轮廓或地面花纹。**为什么**：这是无障碍的基本要求，成本极低。**怎么做**：角色与地砖已有一套程序化绘制，加一个"花纹层"即可。
- **P1｜关卡总览页**：网格列出 30 关的星级与最佳步数，支持按"未满三星"筛选。**为什么**：解谜游戏的核心驱动是"补齐三星"。
- **P1｜提示与星级的关系明示**：用提示会扣星就写在按钮旁边，不扣也写清楚。**为什么**：信息不对称会让玩家干脆不用提示然后卡死。
- **P1｜前 5 关做"教学曲线"复核**：每关只引入一个新概念（移动 → 跳跃 → 镜像延迟 → 反向 → 局部），并确保第 3 关前玩家一定能独立过一次。**为什么**：这款的流失几乎全在前 3 关。
- **P2｜步数/时间双榜（本地）**：给自己一个重复挑战的理由。
- **P2｜关卡编辑器**：镜像解谜的可扩展性很好。
- **P2｜触控摇杆可调**：死区、摇杆位置、按钮大小可调。**为什么**：手机平台跳跃的成败就在这些细节上。
- **P2｜"两面同步"的视觉强调**：当两个角色同时动作时给一个同步的视觉节拍（比如同时的粒子脉冲）。**为什么**：强化"镜像联动"这个核心机制的感知。

**这条最值得先做**：左右形状冗余。这是唯一一条"不做就是排他"的问题。

### 3.8 08 时间碎片 · Time Shards


**现状**
纯原生 HTML/CSS/JS、零依赖的"三线并行因果解谜"可玩原型：8 章 102 关（6 场章末对决、12 关程序化回响）+ 每日实验室 / 无限回环 / 周常裂隙，114 枚碎片、48 项成就、3 个终局。**这是整个合集里工程最扎实的一款**——`tests/run_tests.cjs` 实测 442 项断言全通过（含 106 关可解性搜索与生成器模糊测试），引擎与表现层分离干净，美术层做了背景烘焙、柔光层与 30fps 节流，三线的独立视觉语言与色弱/大字体设置也已在位。缺口集中在**状态管理、百关导航与手机布局**三处。

**主要问题**
1. **道具形同虚设且跨关残留**：`useItem` 只把道具写进 `App.activeItems`，而 `startLevel` / `startEndless` 都**不清空**（`ui.js:134`、`ui.js:992`）；时间怀表与因果胶水**没有任何消费点**（`frozenUntil` 恒为 0，engine 只认 `charmed`）。于是标着"本关内生效"的道具会永久留在后续关卡里。
2. **102 关没有导航层**：主菜单「继续调查」只跳到章节列表（`index.html:39`），存档没有 `lastLevelId`；关卡页只有网格加返回键，没有"下一未通关"、章节切换与筛选，节点也不标记"隐藏碎片未拿 / 未满星"。
3. **手机窄屏卡在两处结构问题**：`#board-links` 画布**没有 CSS 宽高**，位图按 `scrollWidth × dpr` 撑大了 `#board` 的滚动区（实测 844×390 下 `scrollW=1688`、`scrollH=472`）；HUD 目标行被挤到 105px 后截断，dock 溢出到 482px。
4. **引导是一次性长文本**：机制 `tips` 只以 3.6 秒 toast 出现（`ui.js:139`）且无处回看；`App.hintStep`、`App.invalidCount` **从不清零**（`ui.js:1218`、`ui.js:385`），导致下一关点「看提示」直接给末条（剧透）；选好碎片后长按预览被 `if (App.sel) return` 挡掉（`ui.js:437`）。
5. **因果星图只能"回看"**：`graphData()` 只取 `activeEdges`（`ui.js:663`），未操作前是空图；三线 y 坐标硬编码 `60/260/460`，画布高度仅 `62vh`，横屏实测只剩过去线可见。
6. **每日谜题判定可跳过**：`save.labDone` 既当计数又当完成标记（`main.js:150`、`ui.js:959`），**只打第 3 题**就能拿 45 星尘并把三题全标完成。
7. **可访问性与设置形同虚设**（实测）：`viewport` 禁缩放；CSS 全文 **0 处** `:focus` / `:focus-visible` / `outline`；`body.bigfont` 只把物件名 12→13px（HUD 仍是 11~12px）；色弱模式只改轨道边框，**不覆盖目标达成的绿/红**。
8. **表现层零测试覆盖**：`run_tests.cjs` 只 require 引擎与数据，DOM 层没有任何用例——这也是上面第 1、3、4 类问题能长期存在的原因。

**优化建议**

- **P0｜补全道具并复位状态**：在 `startLevel` / `startEndless` 重置 `App.activeItems`；让怀表写 `en.frozenUntil = now + 30000`、在 `engine._storm` 前加 `glued` 分支实现胶水；删掉 `hourglassUsed` / `charmArmed` 两个**写后不读的死字段**。落地方式：给 `ITEM_META` 各加一个 `apply(game, ctx)` 钩子，把道具效果收成一张表。**为什么**：现在花 20~40 星尘买的 5 件道具里，2 件完全无效、3 件跨关残留——这是"付费买到假货"级别的问题。
- **P0｜补一层关卡导航**：存档加 `lastLevelId`（进关即写），「继续调查」直达该关并给「下一未通关」按钮；关卡页加章节下拉、hash 路由（`#/c3l05`）与筛选 chip（未通关 / 未满星 / 含未拿隐藏碎片），节点补 `◈` 与 `★★☆` 角标。**为什么**：102 关里回头找一关要翻 8 章、肉眼扫上百个节点，这是这款游戏**最大的日常摩擦**。
- **P0｜修滚动区与画布尺寸**：给 `#board-links` 加 `width:100%;height:100%`（或 `cv.style.width = bw+'px'`），测量基准从 `board.scrollWidth` 换成 `clientWidth`。**为什么**：`dpr=2` 的机器上棋盘会多出一倍空白可滚，连线画布每帧还要清 4 倍像素——手机上就是"拖不到底 + 掉帧"。
- **P0｜修三处状态残留**：`startLevel` 复位 `hintStep` / `invalidCount`；让 `usedShardIds` 真正记录（碎片 chip 加「已用」角标）；实验室改用「当日已完成题号集合」发奖。**为什么**：否则提示会剧透、"无效操作 3 次自动提示"整局只生效一次、跳打第 3 题白拿 45 星尘。
- **P1｜把"推演"变成"操作前"能力**：长按节点时若已选碎片，就用该碎片生成的**假定事实**跑 `previewFrom`，预览框限 3 行可滚动；星图再加一层灰色"潜在因果边"（取自 `def.rules`，低于阈值标红）。**为什么**：现在两者都只反映已经发生的事，玩家无法计划、只能试错扣完整度——而"可推演"恰恰是因果解谜最大的乐趣来源。
- **P1｜移动端布局重排**：补 `(orientation:landscape)` 与 `(max-height:520px)` 断点；窄屏 HUD 目标行允许两行或点开；无道具时折叠道具栏（现在恒显 5 格，把背包挤成 482px 横向滚动）；点被锁定时间线的节点改中性提示、**不扣 5 点完整度**，HUD 也别把锁定线显示成当前线。
- **P1｜引导改成可交互教学**：把游戏说明模态拆成第 1 章前三关的 3 步 coach mark（选碎片 → 点节点 → 长按看涟漪），`tips` 收进常驻「?」按钮，风暴时就地解释触发了哪条规则。**为什么**：这是合集里教学成本最高的一款，值得专门做。
- **P1｜结算与总览加强**：主菜单补 `★` 总星数与"未满星关卡数"（`totalStars()` **已实现却从未被调用**）；关卡节点显示最佳分与撤销/风暴徽章；结算页提示本关还有隐藏碎片。
- **P1｜让设置真的生效**：删掉 viewport 的 `maximum-scale=1/user-scalable=no`；toast 加 `aria-live="polite"`、弹窗加 `role="dialog"`、补 `:focus-visible` 描边；大字体改 html 级 `font-size` + `rem`；极简模式同时暂停背景 rAF。
- **P2｜拆分 `ui.js`**：按已有边界拆成 `ui-art.js`（Art/FX，1223 行起）、`ui-graph.js`（596 行起）、`ui-modes.js`（952 行起），沿用 IIFE 挂 window 的写法；顺手删掉 `tools/patch_*.py`（字符串替换式补丁，README 已注明可删）。
- **P2｜补表现层测试**：把探针脚本固化成冒烟用例（进关 → 用碎片 → 结算 → 重进，断言道具 / 提示 / 计数复位与存档写入）。**为什么**：这一条能一次性挡住上面第 1、3、4 类的回归。
- **P2｜文案与每日内容**：修 `'时间 complete'` 的中英混排（`main.js:251`）；实验室每题标「本章机制」并显示刷新倒计时与连续天数，主菜单给未完成角标。

**这条最值得先做**：关卡导航。102 关是这款游戏最大的资产，也是最容易变成"找关地狱"的地方。

### 3.9 09 星穹拓荒 · Stellar Frontier


**现状**
程序生成星系殖民 Roguelike，一局一宇宙，永久死亡 + 遗产成长。有四种模式（星图长征/深空漫游/每周挑战/沙盒）、九站跃迁、科技树、防御工事、陨石与星兽。本轮修掉了三个把玩家"冻住"的问题：**首次进入弹出的操作说明在小屏上按钮被裁掉、Esc 又关不掉，导致对局永久暂停**（这直接造成了"不能移动、人傻站"）；**教学面板被 CSS 在所有手机上强制隐藏**；**教学只在星图长征模式里开**。此外还修了我上一轮美术改动引入的布局事故（`.glass{position:relative}` 覆盖了 8 个元素的绝对定位）。

**主要问题**
1. **教学结束后的目标真空**：教程是 6 步（降落→采矿场→50 矿石→聚变发电机→居住舱→抵御事件），走完后玩家进入"开放但无引导"的状态。
2. **电力/覆盖范围不可视**：能源赤字是核心压力来源，但玩家看不出"哪条线过载、哪栋楼没电"。
3. **里程碑存档"30 秒销毁"的提示不够醒目**（README 里提到"读取后30秒销毁"）。这个规则比较特殊，玩家一旦没看见就可能失去进度。
4. **事件密度在后期可能失控**：威胁等级越高事件越频繁，缺少"喘口气"的节奏控制。
5. **移动端单指拖动与建造点击存在冲突风险**（拖动视角 vs 点击放置）。

**优化建议**

- **P1｜教程后接"软目标"链**：教学结束后自动接一段非强制的建议目标（"建议：把电力转正""建议：造 1 座炮塔对抗第 3 站"），完成后淡出。**为什么**：把"教学结束"到"我能自己玩"之间的空档补上。
- **P1｜电力与覆盖可视化**：点选建筑时高亮它的供电链与覆盖半径；顶栏电量条在赤字时标出"哪几栋在吃电"。**为什么**：能源是这款游戏的命脉，看不见就等于不可控。
- **P1｜存档规则显著化**：进入对局时用一次性横幅明确"本局为里程碑存档，读取后 30 秒销毁"，并在存档按钮上标倒计时。**为什么**：特殊规则必须显著，否则就是陷阱。
- **P2｜事件节奏阀门**：连续两次负面事件后强制插入一次喘息期（或降低下一次事件强度）。**为什么**：永久死亡 + 事件连击 = 挫败感堆积。
- **P2｜多档位与"快速重开"**：不同难度/种子各留一档，并在结算页提供"用同一种子重开"。**为什么**：Roguelike 的乐趣在重试，重试成本要低。
- **P2｜移动端建造独立按钮**：把"拖动视角"和"放置建筑"分配到不同手势（例如放置时锁定视角）。**为什么**：消除误操作。
- **P2｜遗产商店的引导**：首次进入档案页时用一句话说明"死亡不是结束"。**为什么**：这是这款游戏最重要的心理设计，藏起来太可惜。

**这条最值得先做**：教程后的软目标链。它把一个"开放世界式的空档"变成"有方向的推进"，对留存的影响最直接。

### 3.10 10 情绪花园 · Emotion Garden


**现状**
治愈系情绪表达游戏（纯前端零依赖）：用颜色 / 文字 / 音乐说出此刻心情，本地解析成 6 类情绪，生成 24 种 × 3 变异的程序化植物，按 5~24 小时真实时间经五阶段开花。垂直切片完成度很高——表达 → 播种 → 照料 → 生长 → 收获 → 生态闭环、双副本存档、72 图鉴、26 成就、12 章"心灵旅程"、8 个生态事件、冥想、回顾信、字号 / 高对比 / 低刺激设置都已落地；离屏花瓣叶片精灵与 8 种花形也在上一轮完成了美术升级，分层清晰、注释完整。

**主要问题**
1. **分享卡把玩家写的原句画进了 PNG**（`ui.js:823` 绘制 `pl.note`），与界面上「分享的是花，不是心情的原文」以及 README 里的合规承诺**直接矛盾**——实测导出的卡片上出现了「我今天特别难过想一个人待着」。对一款以"安全表达情绪"为卖点的产品，这是最严重的一类问题。
2. **颜色路径名存实亡**：`ui.js:284` 用中文词条的 `cat/intensity` 覆盖了 `parseColor` 的结果。实测选纯红 8°、再点「平静如水」，得到 `calm` / 强度 5，但颜色值仍是红色的 -0.85——**类别与数值自相矛盾**；而且不点中文词条就无法继续，等于强迫用户从 8 个中文短语里挑一个。
3. **凋谢不可挽留，且文案不实**：`checkWither` 只看绽放后 72 小时真实时间，浇水 / 剪枝 / 道具**全部无效**（实测刚浇过水仍枯萎）；×360 加速时存活期只有 12 分钟；而回顾信却写着「替你浇过水」。
4. **目标链互锁且不可达**：Lv30 需 152,978 经验（≈4,500 株）、Lv50 需 587,651（≈17,000 株），而 64 格满园最优配比下实测生态评分上限只有 852——策划案里的 1000 与成就 `a_eco750` 都够不到。
5. **玩家那一株没有被记住**：`dex` 只存 `{n, variants, first, species}`（`game.js:442`），图鉴缩略图用 `'dex'+物种id` 的**假种子**重绘（`ui.js:513`），日记又在 400 条处硬截断——"独一无二的那一株"和"回忆"都没留住。

**优化建议**

- **P0｜分享卡默认不写原句**：在 `ui.js:823` 增加「在分享卡上写这句话」开关（**默认关**），并把弹窗文案改成如实描述。**为什么**：隐私承诺与实际行为不一致，是这类产品不能接受的；默认关 + 显式勾选既保住隐私又不剥夺表达欲。
- **P0｜让色轮真正生效**：改为 `parseColor` 直出，主按钮换成「就用这个颜色」，8 个中文词条降为**可选的校准**。**为什么**：一次解决三个问题——颜色路径名副其实、色盲 / 低文字用户不必强行选中文短语、也消除了类别与数值自相矛盾。
- **P0｜给"失去"留出口**：凋谢时提供「留在花园」（进装饰层永久陈列 + 保留原句）；`×360` 只加速生长、**不加速 `bloomedAt`**；删掉回顾信里「替你浇过水」的不实承诺。**为什么**：治愈系游戏里"不可挽回的失去 + 一句假话"是最伤人的组合。要么让它可挽留，要么让它诚实。
- **P0｜修移动端布局**：`garden.js:668/759` 的石板径与围栏在 390px 宽下实测挤到 180/210、176/214 **完全重叠**，应改按宽度比例排布或窄屏隐藏；工具条补 `env(safe-area-inset-*)`；窄屏限制最大网格（8×8 时单格仅 43.9px、缩放触底 0.55）。
- **P1｜重排成长曲线**：`expNeed` 从 `60·l^1.6` 降到 `60·l^1.15`（Lv30 从 15 万降到约 3.5 万），地块扩张改挂「累计收获」，生态评分满分重标为 850。**为什么**：现有曲线需要种 4,500 株才能到 Lv30，这已经不是"长期目标"而是"不可能"。
- **P1｜图鉴记住种子与原句**：`dex` 增存首次 `seed` 与 `note`（可隐藏），缩略图改用**真实种子**重绘，植物详情加「生成纪念卡」复用 `openShare`。**为什么**：这是"每一株都独一无二"这个卖点的落地；用假种子重绘等于每株看起来都一样。
- **P1｜日记按月分片存储**替代 400 条硬截断；设置里显示「已记录 N 天 / 占用 KB」；增加导出 txt/csv 与「只清空情绪原文、保留花园」。**为什么**：情绪日记的价值随时间增长，截断等于主动销毁用户资产。
- **P1｜可访问性补课**：全站 `tabindex`/`aria` 数量为 0、无 Esc 关模态、日历圆点只有颜色、`--ink-l` 对比度仅约 3.2:1、低刺激模式不作用于 CSS 动画、viewport 禁缩放。建议补键盘激活与 Esc、圆点加 `●〜▽▲✳☾` 符号冗余、说明文字默认加深、允许缩放。**为什么**：这款游戏面向的正是情绪敏感人群，可用性门槛应当比其它几款更低。
- **P1｜音乐补深度**：`MusicPlayer.play`（`audio.js:142`）用 `Math.random()` 抽音，实测同一首曲两次播放音符不同、全曲只有约 10 个音。改用 `EG.RNG(track.id)` 生成确定性旋律，曲库标出情绪与关键片段，导入支持选段分析。**为什么**：音乐是这款游戏的三条表达通道之一，现在它既不可复现也不成曲。
- **P1｜音频开关修正**：设置里关 BGM 只调用 `BGM.stop()`（仅清定时器），环境底噪仍在 `bgmGain=0.5` 下循环。让 `stop()` 归零增益并停掉 `_noise`。**为什么**：这是"关了没关掉"的典型可用性 bug。
- **P2｜交互细节**：收获与开垦地块单击即不可逆（`ui.js:175`、`main.js:118`）应二次确认；调光 60min / 旋律 20min / 剪枝 4h 的冷却需显示倒计时；`plant()` 中 `record()` 与 `bumpTask('record')` 重复导致"种一株"任务记 2 次；教学植物按钮写「浇水 +8」实际给 40。
- **P2｜性能**：实测空园约 26~30ms/帧、满园 64 株约 40ms/帧，主要开销是**每帧重建**天空 / 山 / 草 / 装饰（约 40 个径向渐变 + 近 200 条草叶 + 90 颗星 + 12 株装饰花）。建议把静态背景烘焙到离屏画布，仅在季节 / 昼夜 / 生态变化时重建。**为什么**：这是本合集里最"吃"性能的一款，而它的画面本来并不需要每帧重画。

**这条最值得先做**：分享卡的原句问题。它是**唯一一条"做错了会伤害用户"**的建议，优先级高于所有体验优化——把开关默认关掉、文案改对，改动量很小，但性质完全不同。

## 四、横向共性问题（十款都有，改一处收益十次）

逐款建议之外，有几类问题在十款游戏里反复出现。它们比单款优化更值得优先处理，因为**一次规范能同时改善十款**。

### 4.1 新手引导：需要一套统一规范

本轮给《深渊词条》《幻境争锋》《镜像迷城》补了引导，修好了《星穹拓荒》的引导，但《余烬之城》《时间碎片》《情绪花园》的引导仍是"读文档"式的。更重要的是，**现有引导的实现方式彼此独立**——每款各写一套浮层、各用一套 localStorage key。建议抽出统一规范（不一定要抽公共代码，但要有统一契约）：

| 契约项 | 要求 | 理由 |
|---|---|---|
| 触发 | 首次进入自动触发，落一个 `*_tut_v1` 标记 | 老玩家不该被打扰 |
| 跳过 | 必须有一眼可见的「跳过」，且 Esc 也能退出 | 被引导卡住比不引导更糟 |
| 重看 | 菜单/设置里必须能重看 | 玩家常常跳过之后才后悔 |
| 不阻塞 | 引导期间的覆盖层设 `pointer-events:none`，只有按钮吃事件 | 本轮的引导都做到了，应固化为规范 |
| 步数 | 5~9 步，每步只教一件事，尽量用"做一次"而不是"读一段" | 超过 9 步的引导完成率会陡降 |
| 判定 | 能自动判定的就自动推进（买到英雄→下一步） | 减少点击负担 |

**反例参考**：《星穹拓荒》原本的做法是"弹一整页六段操作说明 + 暂停世界"。本轮虽然把它修得关得掉了，但**"一次性读完一页表格"本身就是最弱的引导形态**。同类问题在《星火拓荒》也存在（6 页页签说明）。建议长期都把这类大文档降级为"随时可查的手册"，而把首次体验交给分步引导。

### 4.2 移动端：多款游戏在手机上等于不可用

这是**整个合集最大的系统性缺口**。逐款盘一下输入方式：

| 游戏 | 手机可用性 | 问题 |
|---|---|---|
| 02 星火拓荒 | 严重受限 | 建造依赖右键菜单/左键放置，手机没有右键 |
| 04 深渊词条 | 不可用 | 键盘 WASD + 鼠标开火 |
| 05 幻境争锋 | 可用但精度差 | 拖拽放子在窄屏上容易放错 |
| 07 镜像迷城 | 基本可用 | 虚拟摇杆需要手感调校 |
| 08 时间碎片 | 布局风险 | 三栏并排在窄屏上会挤压 |
| 09 星穹拓荒 | 可用 | 拖动视角与放置建筑的手势冲突 |
| 06 回声 Echo | 可用 | 本就以"点按屏幕"为主 |
| 03 拓城记 | 可用 | 网格点击精度 |

建议按这个顺序处理：**先给 04 和 02 加触控方案**（这两款手机上完全不能玩），再统一调校其余几款的手感。具体做法上，最小可行方案是"左下虚拟摇杆 + 右下动作按钮"，而不是重写输入层——各款的输入都集中在少数几处（例如 `main.js` 的 `bindInput`），改造成本可控。

### 4.3 存档：单档 + 清缓存即丢，是长期陪伴的硬伤

现状是每款一个 localStorage key、单存档位。带来三个问题：

1. **误操作无退路**：模拟经营和剧情游戏尤其需要"回退一步"。
2. **清缓存即清进度**：浏览器清理缓存、换设备、换浏览器都会丢。而《时间碎片》有 102 关、《拓城记》有 11 个里程碑——丢失成本很高。
3. **无法迁移**：玩家换手机就重来。

建议分两步：
- **P1｜存档导出/导入**：把存档序列化成一段文本或二维码，玩家可以自己保存。**为什么**：这几乎零成本（不需要服务器），却能一次性解决迁移和备份问题。实现上各款的存档已经是 JSON，加一个复制/粘贴入口即可。
- **P1｜关键游戏加"自动存档时间线"**：保留最近 5~10 次自动存档，可回退。**为什么**：比多档位更省玩家心智，也更有效防误操作。

### 4.4 可访问性：现在只有零星考虑

十款里我明确看到无障碍相关设计的是《镜像迷城》（色盲考虑在本轮被点出）和《回声》（声纹可视化）。其余几款普遍缺少：

- **色盲冗余**：《拓城记》的季节色、《情绪花园》的情绪色、《幻境争锋》的羁绊色都只靠颜色区分。建议凡是"只用颜色区分信息"的地方，都补一个形状/图案/文字冗余。
- **字号与对比度**：《星穹拓荒》有字号档位（`body.fs1/fs2`）值得推广；其余几款的正文在手机上都偏小。
- **纯键盘可玩**：剧情类（01）与解谜类（07、08）应做到全键盘可操作。
- **动效敏感**：多款有粒子、屏震、闪烁（04 的受击闪白、05 的战斗特效）。建议提供"减少动效"开关——这不是小众需求，部分玩家会因闪烁不适。
- **静音可玩**：《回声》是极端例子，但《情绪花园》的音乐模式也依赖听觉。

### 4.5 代码组织：大文件正在变成风险

实测当前体积：`3/js/render.js` 105.9KB、`4/js/game.js` 136.2KB、`8/js/ui.js` 89.5KB、`5/index.html` 149.3KB、`1/余烬之城.html` 172.6KB。这个体量本身不是错（无构建工具的前提下，少文件反而简单），但带来两个具体风险：

1. **改一处怕碰别处**：本轮就真实发生过两次——子任务用 PowerShell 批量替换把三个文件的中文编码弄坏了；我上一轮给 `.glass` 加 `position:relative` 覆盖了 8 个元素的绝对定位，直到量元素坐标才发现。
2. **缺回归测试**：目前只有《时间碎片》（442 项）和《镜像迷城》（关卡校验器）有自动化测试。

建议：
- **P1｜给"表现层改动"加一个通用布局体检**：本轮我做的 `diag-layout-health.js` 就是雏形——扫描所有定位元素是否跑出视口。它可以变成十款通用的冒烟测试。
- **P1｜把"隐形遮罩抢点击""调用了不存在的方法"两类静态检查固化**：本轮靠这两个检查抓出了《回声》的两个致命 bug（隐藏菜单挡住启动页、`this.initFX is not a function`）。它们都是几十行脚本，值得每款都跑。
- **P2｜给大文件加注释分区表头**：`render.js` / `game.js` 这类文件在顶部列一个"函数索引"，能显著降低阅读成本。

### 4.6 小噪音：favicon 404

十款游戏在浏览器控制台都会报一条 `favicon.ico 404`。功能上无影响，但它有两个实际代价：一是每次排查问题时都要先排除它，二是控制台第一眼就是红色错误会让玩家以为游戏坏了。**建议统一加一组内联 SVG favicon**（几行代码，不用外部文件），顺手也能让浏览器标签页更易辨认。

## 七、一句话总结

十款游戏的**技术底座（零依赖、零素材、离线可玩）是整个项目最值钱的资产**，美术也已经在上一轮补到了不错的水平。现在真正的短板集中在三处：**新手引导不统一、移动端基本不可用、存档太脆**。这三件事都不需要重写游戏，做完之后这十款才真正具备"发给任何人、任何设备都能玩下去"的完整度。

**一个必须说明的口径问题**：`_tools/probe.mjs` 默认带 `--disable-gpu`（软件光栅），这个环境下的绝对帧率**不能代表真机**。上表中带"GPU 路径"的两行才是接近真实的值，其余是"最坏情况下限"。这也是为什么我不建议用软件光栅下的数字去判断"某款游戏是不是太卡"——判断依据应该是那个 4.66ms 的每帧耗时（它是 CPU 侧真实成本）。
