以下数据全部来自本次迭代中的 headless Edge + CDP 实测（`_tools/` 下的探针脚本）。"主色占比"指画面中最大单块颜色占全屏的比例——**数值越低说明画面越不像"大色块"**；"精确颜色数"越高说明渐变与纹理越丰富。

**怎么读这张表**：十款游戏的"主色占比"全部下降、"精确颜色数"全部上升，说明这一轮美术优化是普遍生效的，而不是个别游戏的偶然波动。其中 03 与 08 的提升幅度最大（主色占比降到 10% 上下、颜色数翻一个数量级），因为它们原本是"整片纯色地块"的形态；06 回声的绝对值仍然最高（70.4%），这是**设计使然**——它是一款以黑暗为核心的游戏，压暗是刻意的，所以它的目标不是"低主色占比"而是"在黑暗中仍可读"。

### B.3 性能

| 场景 | 数据 | 说明 |
|---|---|---|
| 02 星火拓荒（GPU 路径） | **191 fps**（最差帧 16.7ms） | 真实浏览器合成路径 |
| 09 星穹拓荒（GPU 路径） | **167 fps**（最差帧 20.9ms） | 同上 |
| 02 星火拓荒（软件光栅） | 53 fps | 无 GPU 时的降级表现 |
| 05 幻境争锋（软件光栅） | 59~61 fps | `drawBoard()` 仅 0.045ms/帧 |
| 04 深渊词条（软件光栅） | 60 fps | `render()` 0.99ms/帧 |
| 07 镜像迷城（软件光栅） | 59 fps（最重关卡 56） | 相比原版 60fps 几乎无损 |
| 10 情绪花园（软件光栅） | `render()` 4.66ms/帧 | 预算 16.6ms；但满园 64 株升到约 40ms/帧 |
| 08 时间碎片（软件光栅） | 星图 22 fps（原 19） | 反而更快，因为做了缓存重写 |

**一个必须说明的口径问题**：`_tools/probe.mjs` 默认带 `--disable-gpu`（软件光栅），这个环境下的绝对帧率**不能代表真机**。上表中带"GPU 路径"的两行才是接近真实的值，其余是"最坏情况下限"。这也是为什么我不建议用软件光栅下的数字去判断"某款游戏是不是太卡"——判断依据应该是那个 4.66ms 的每帧耗时（它是 CPU 侧真实成本）。
