**版本** v1.0　**范围** `D:\游戏` 下全部十款游戏　**线上地址** http://47.94.215.84/games/

## 一、这份文档是什么

这份意见书针对 `D:\游戏` 目录下的十款自研网页游戏，逐款给出**可执行的修改与优化建议**。它不是在赞美现状，也不是泛泛而谈"要提升体验"，而是尽量回答三个问题：**现在哪里不好、为什么会这样、具体怎么改**。

需要先声明这份文档的**证据基础**，以免读者误判可信度：

| 证据类型 | 说明 |
|---|---|
| **实测证据** | 本轮与上一轮迭代中，我用 headless Edge + CDP 真实加载过每一款游戏，抓取过 console 报错、页面异常、元素坐标、帧率、以及游戏内部状态（通过 `--eval` 注入断言读取 `G`/`SF` 等运行时对象）。文中"实测"字样均指这类证据 |
| **代码证据** | 阅读过各款游戏的核心源码，文中指出的根因大多能对应到具体文件与函数 |
| **推断建议** | 优化建议本身属于"我认为这样做会更好"，其中一部分基于同类游戏的设计惯例，**并未经过玩家验证**。这类内容我会明确写成"建议"，而不是"必须" |

不在这份文档里的内容：**没有做过真实玩家测试**，没有留存率/时长等数据，也没有做过付费或商业化分析。所有关于"玩家会怎样"的判断都是基于设计逻辑的推断。

## 二、总体评价

### 2.1 共同的技术底座（这是十款游戏最大的优势）

十款游戏共享一套非常克制的技术选择，值得先说清楚，因为**后面所有优化建议都必须在这个前提下讨论**：

- **零依赖、零素材**：没有 CDN、没有 npm 包、没有图片/音频文件、没有 ES module、没有 `fetch`。所有美术都是 Canvas/CSS/SVG 程序化生成。
- **`file://` 双击可玩**：十款全部实测过，直接双击本地 HTML 就能跑，唯一代价是 `file://` 下 `localStorage` 在部分浏览器受限（有游戏已做 `try/catch` 兜底）。这意味着**分发成本几乎为零**——发给别人一个文件夹就能玩。
- **存档在浏览器本地**：各用各的 localStorage key，互不冲突。
- **性能余量充足**：在带 GPU 的真实浏览器里，实测《星火拓荒》191fps、《星穹拓荒》167fps，远超 60fps 目标。

这套底座的代价也很明确：**没有构建工具链**，所以代码组织是"多文件挂全局变量"（`G`、`SF`、`MMGame` 这类），单文件体积偏大（最大的 `8/js/ui.js` 约 91KB、`3/js/render.js` 约 105KB）。这在"改一处不影响别处"上是加分，在"新人接手"和"回归测试"上是减分。

### 2.3 优先级矩阵

我按「影响面 × 修复成本」把全部建议压成一张表。**P0 是本轮已修的**（列出以便追溯），P1/P2 是后续建议。

| 优先级 | 含义 | 典型项 |
|---|---|---|
| **P0** | 已修：不修就玩不下去 | 回声点不进、星穹被弹窗冻死、深渊进不了下一层、拓城资源不循环 |

## 三、逐款修改与优化建议

### 3.1 03 拓城记 · 中古殖民模拟

**现状**
自顶向下网格经营的殖民地模拟，居民由「住房/食物/娱乐/医疗/信仰」五类需求驱动。本轮刚修掉四个真问题：资源不会再生、节奏过快、基建无产出、居民数量失控。现在有了可再生资源层（`js/resources.js` 的 `G.NAT`）、4 秒/天的节奏与 0/1/2/3 档速度、真正结算的森林加成与按需求比例分摊的用工、以及"一名居民对应一个行走单位"的收敛，居民可点选查看职业与当前任务。**它的美术层（23 种建筑独立剪影、不规则地块边界、云影与昼夜分级）在本轮之前就已做完，质量不错。**

**主要问题**
1. **生产链对玩家是黑箱**：虽然本轮让"有产出"变得可见（头顶浮字、顶栏涨跌、昨日产出表），但"谁供给谁、哪个环节卡住"仍然只能靠猜。玩家看到石料不涨，无法一眼判断是没矿、没人、还是仓储满了。
2. **目标链 11 个里程碑的存在感偏弱**：它是这款游戏真正的长线引导，但埋在面板里，玩家更容易陷入"看着城市运转但不知为何而玩"。
3. **季节与灾害缺少前瞻预警**：秋冬粮荒是设计核心（"秋冬囤粮是生存关键"），但玩家只在粮仓见底时才后知后觉。
4. **居民寻路的可读性**：本轮加了目的徽标，但大量居民同屏时仍然难以判断谁是"去上班"、谁是"在家"。
5. **存档只有单档**：一次误操作（比如拆错一片城区）没有退回余地。

**优化建议**

- **P1｜生产链透视面板**：在城市面板里加一行「本日生产 → 消耗 → 净变化」的流向表，把每类资源拆成"建筑产出 / 居民消耗 / 浪费"。**为什么**：这是经营类游戏最标准的可读性设施，做了之后"基建没收入"这类困惑会从根上消失。**怎么做**：`economy.tick` 已经记录了 `lastProd/lastWant/lastOverflow` 快照，直接聚合成表即可，不需要新增模拟逻辑。
- **P1｜把目标链顶到主界面**：在顶栏放一条常驻的「当前目标 + 进度」窄条（类似《星穹拓荒》的教学任务面板），点开才是完整 11 项列表。**为什么**：长线目标不显眼等于没有。
- **P1｜季节/灾害前瞻预警**：入秋时用横幅提示"距冬季 N 天，预计粮食缺口约 M"，并给出建议动作。**为什么**：把"事后惩罚"变成"事前规划"，是这类游戏体验差异最大的一个改动。
- **P1｜建筑信息面板补齐明细**：产出/维护/用工/周边资源蓄积/是否满负荷，一屏说清。**为什么**：玩家花金币建的建筑，必须能一眼看懂它现在干得好不好。
- **P2｜多存档槽位（3~5 个）+ 自动存档保留最近 N 份**：**为什么**：模拟经营玩家天然会"试错后想反悔"。
- **P2｜居民寻路可视化开关**：放大到一定倍数时显示"家→工作地"的连线。**为什么**：直接回应"这么多人跑来跑去到底在干嘛"。
- **P2｜暂停时允许规划**：暂停下建建筑、改分工。**为什么**：降低操作压力，也顺手解决"速度太快看不懂"的残余。
- **P2｜关键事件日志可回看**：把事件横幅收进一个可滚动的时间线。**为什么**：错过横幅的玩家不该永久失去信息。

**这条最值得先做**：生产链透视面板。它用已有的数据快照就能做出来，却能一次性解决"为什么没收入""资源去哪了""仓储是不是满了"三个高频困惑。

### 3.2 04 深渊词条 · 肉鸽打宝

**现状**
俯视角动作肉鸽。本轮修掉三处：**楼梯房没有可交互出口**（这是致命的——`makePickup('next')` 全项目只在击杀 Boss 分支出现，而第 1 层没有 Boss，理论上永远无法通过）、攻击手感呆滞（投射物只看当前帧落点导致掠射失效、点击无输入缓冲）、以及完全没有新手引导。修完后实测**连续通过 1→2→3→4 层**，按下到开火从 16.5ms 降到 0ms，并补了 9 步引导。第一轮还做过地牢美术（石板地面、伪 3D 墙体、1/4 分辨率光照层、后处理烘焙）。

**主要问题**
1. **"封印"机制虽然现在有提示，但仍可能让新玩家困惑**：锁定态提示是文字（"清空本房间敌人后开启"），但如果最后一个敌人卡在角落或玩家没看见，仍然会停顿。
2. **缺少"我这一局在往哪走"的全局感**：小地图与箭头已有，但没有整层的进度感（还剩几个房间、离 Boss 还有多远）。
3. **词条/装备缺少对比与保护**：肉鸽的乐趣在搭配，但玩家很难判断"新掉的这件是不是比身上好"，也容易误操作。
4. **掉落拾取需要手动逐个跑**：刷宝类游戏里，捡东西的时间占比过高会稀释爽感。
5. **移动端触控未明确**：这款依赖键盘（`KeyW/A/S/D` + 鼠标开火），手机上无法正常游玩。

**优化建议**

- **P1｜房间清空进度常驻显示**：在 HUD 上显示"本层进度 3/7 房间 · 剩余敌人 N"。**为什么**：直接消除"我是不是卡住了"的焦虑。**怎么做**：`enterRoom` 已经维护 `room.cleared`，聚合计数即可。
- **P1｜"最后一个敌人"高亮**：房间只剩 1 个敌人时，给它加描边并让镜头轻微提示。**为什么**：卡关 90% 的情况就是那一个漏网的怪。
- **P1｜装备对比浮层**：拾取时按住某键显示"与当前装备的数值差（+/-）"。**为什么**：这是刷宝类游戏的标配，缺失会让玩家干脆不捡。
- **P1｜移动端虚拟摇杆 + 开火按钮**：左下摇杆移动、右下按钮开火/冲刺。**为什么**：不做这一条，手机上这款游戏等于不存在。
- **P2｜磁吸拾取**：一定范围内的金币/消耗品自动吸附。**为什么**：把时间还给战斗。
- **P2｜本层小地图进度环**：小地图外圈画一圈房间进度。**为什么**：给玩家"快到了"的期待感。
- **P2｜Boss 层预告与准备房**：进 Boss 前给一个可以整理装备、补血的房间。**为什么**：突然进 Boss 房被打死是最挫败的体验。
- **P2｜伤害数字分级与暴击高亮**：让"这一下打得很重"可感知。**为什么**：手感的一半来自反馈而不只是帧数。

**这条最值得先做**：装备对比浮层。它把"捡不捡"这个高频决策从猜测变成比较，直接影响刷宝循环的爽感。

### 3.3 05 幻境争锋 · 战棋自走棋

**现状**
单文件自走棋。第一轮做了大幅美术升级（棋盘整块离屏烘焙、5 种地形材质、6 职业×6 种族英雄立绘替换全部 emoji、三层浮空岛视差背景、战斗演出），本轮补了 9 步聚光灯引导（买东西→备战席→拖上棋盘→调站位→羁绊→经济→开战）。实测引导期间 `pointer-events:none`，玩家照常买人、拖拽、开战。

**主要问题**
1. **阵容无法保存**：自走棋的核心乐趣是"研究出一套阵容再反复用"，每次从头摆非常消耗耐心。
2. **战斗过程"看不懂"**：战斗全自动，但玩家不知道谁打了多少伤害、这套阵容强在哪、输在哪。
3. **商店概率不透明**：不同等级的英雄出现概率是这类游戏的策略核心，隐藏它会让决策变成赌博。
4. **羁绊推荐缺失**：新手面对 23 个英雄 + 多套羁绊，不知道往哪个方向凑。
5. **触控拖拽在小屏上精度不足**：棋盘格子小，拖歪了就放错位。

**优化建议**

- **P1｜阵容预设（3~5 套）**：保存站位与英雄，一键套用。**为什么**：这是自走棋留住玩家的关键功能，没有它每局都在重复劳动。
- **P1｜战斗结算面板**：战斗后显示每个单位的伤害/承伤/治疗排行。**为什么**：把"自动战斗"从黑箱变成可分析对象，玩家才有优化动力。
- **P1｜商店概率公示**：在商店旁边显示"当前等级下各费卡出现概率"。**为什么**：这是策略深度的来源，藏着只会让玩家觉得随机。
- **P1｜羁绊推荐/高亮**：当玩家已凑到某羁绊 2/4 时，把能补齐的英雄在商店里高亮。**为什么**：新手最需要的就是"下一步买谁"。
- **P2｜战斗回放/倍速细化**：现在有加速，建议再加一次"逐回合"或"关键帧pause"。**为什么**：让人有机会看清那一波团战是怎么崩的。
- **P2｜触控吸附与放大镜**：拖拽时把目标格放大并吸附。**为什么**：直接解决小屏精度问题。
- **P2｜连续对局与局内成长记录**：记录最近 N 局的阵容与名次。**为什么**：给非排位玩家一个自查工具。
- **P2｜音效层次**：不同稀有度/羁绊激活给不同的听觉反馈。**为什么**：自走棋的爽感很大一部分来自"胡牌"的即时回馈。

**这条最值得先做**：阵容预设。它直接对应"每局重复劳动"这个最大的流失点。

### 3.4 06 回声 Echo · 声音解谜冒险

**现状**
这款是整个合集里**概念最锋利**的一款：玩家扮演失去视觉的"聆听者"，全程零文字，靠探测音、录音、回放、和弦叠加解开谜题。第一轮修掉了两个致命问题——隐藏主菜单用 `pointer-events:auto` 挡住了启动页导致**点「开始」毫无反应**，以及 `this.initFX is not a function` 导致**进关卡直接崩**。之后又做了游戏内美术升级（环境低频斑块、墙体辉光、声波多层光环、尘埃、后处理分级），并调低了整体亮度以免破坏"黑暗"的基调。

**主要问题**
1. **对听障用户完全不可用**：声音是唯一信息通道，而游戏里的"声纹可视化"虽然存在，但只是辅助，关键判定仍依赖听觉。
2. **对普通用户的理解成本极高**：零文字是设计美学，但玩家进入第一关后没有任何"我知道了"的时刻，很容易在 2 分钟内退出。
3. **长时间高频音可能造成听觉疲劳**：探测音与回声环是持续触发的。
4. **卡关时缺少渐进式帮助**：代码里有"卡住 180 秒出现箭头提示"的机制，但 3 分钟对一款 5 分钟一关的游戏来说太长。
5. **缺少关卡编辑器或沙盒创作**：这类机制天然适合让玩家造谜题。

**优化建议**

- **P0｜把"视觉化"提升为可选的一等公民**：在设置里提供"视觉辅助：关 / 基础 / 完整"三档，完整档把声音的全部属性（延迟→距离、音调→体积、音色→材质、左右→方位）用图形明确表达出来。**为什么**：这不只是无障碍——很多玩家在嘈杂环境（地铁、办公室）会静音玩游戏，视觉辅助决定了他们能不能玩。
- **P1｜首关做成"引导关"但保持零文字**：用图形/色调/节奏在 30 秒内教会"点一下会发声、声波会照亮东西"。**为什么**：概念型游戏必须在前 60 秒交付一次"啊哈"。**怎么做**：把现有 `l1` 拆成三个微型阶段，每阶段只引入一个新操作，用同一套声波视觉语言示范。
- **P1｜把提示时间从 180 秒降到 60 秒，并分级**：60 秒给一次轻微的方向色彩提示，120 秒给明确箭头。**为什么**：手机上玩家耐心更短。
- **P1｜响度与频率保护**：给探测音加一个渐入包络，并在设置里提供"温和模式"（限制峰值音量与高频能量）。**为什么**：长时间游玩不应该让人头疼。
- **P2｜关卡编辑器 + 分享码**：让玩家用同一套机制造谜题，用 URL/字符串分享。**为什么**：这类机制的自传播能力极强，而且几乎不增加服务器成本（分享码可以完全放在链接里）。
- **P2｜"听觉档案"**：把玩家收集到的声纹做成可回放的图鉴。**为什么**：给收集行为一个明确的落点。
- **P2｜节奏可调**：允许把回声延迟整体缩放（现在有"回声校准"滑杆，可以扩展成"难度"）。**为什么**：听感差异很大，硬编码的延迟对部分玩家就是噪声。

**这条最值得先做**：三档视觉辅助。它同时解决无障碍、静音场景、和理解成本三个问题，是这款游戏从"概念惊艳但玩不下去"变成"真的能玩"的关键一步。

### 3.5 07 镜像迷城 · Mirror Maze

**现状**
2.5D 横版对称光学解谜：双子（左·青）与长（右·橙）被真实之镜分隔，**一套输入同时驱动两个角色**。第一轮做了镜面/光束/场景/角色的美术升级（冷→暖镀膜渐变、5 层辉光光束、石砖与金属格栅材质），本轮补了**核心 8 步 + 机关 3 步**引导，聚光灯按世界坐标投影精确套在机关格子上（误差 ≤1px）。30 关全部通过校验器。

**主要问题**
1. **左右两侧靠颜色区分（青/橙）**：色盲玩家会失去最核心的方位线索。
2. **"一套输入驱动两人"是最大卖点也是最大门槛**：即使有引导，前几关仍可能让玩家手忙脚乱。
3. **缺少关卡筛选与进度总览**：30 关 + 星级，想回头补三星要逐个翻。
4. **提示系统的成本不透明**：用了提示会不会影响星级，玩家不清楚就不敢用。
5. **移动端虚拟摇杆与跳跃的手感**未经过专门调校。

**优化建议**

- **P0｜给左右两侧加形状/纹理冗余**：除了青/橙，再给左侧加"细纹/圆点"、右侧加"粗纹/斜纹"的角色轮廓或地面花纹。**为什么**：这是无障碍的基本要求，成本极低。**怎么做**：角色与地砖已有一套程序化绘制，加一个"花纹层"即可。
- **P1｜关卡总览页**：网格列出 30 关的星级与最佳步数，支持按"未满三星"筛选。**为什么**：解谜游戏的核心驱动是"补齐三星"。
- **P1｜提示与星级的关系明示**：用提示会扣星就写在按钮旁边，不扣也写清楚。**为什么**：信息不对称会让玩家干脆不用提示然后卡死。
- **P1｜前 5 关做"教学曲线"复核**：每关只引入一个新概念（移动 → 跳跃 → 镜像延迟 → 反向 → 局部），并确保第 3 关前玩家一定能独立过一次。**为什么**：这款的流失几乎全在前 3 关。
- **P2｜步数/时间双榜（本地）**：给自己一个重复挑战的理由。
- **P2｜关卡编辑器**：镜像解谜的可扩展性很好。
- **P2｜触控摇杆可调**：死区、摇杆位置、按钮大小可调。**为什么**：手机平台跳跃的成败就在这些细节上。
- **P2｜"两面同步"的视觉强调**：当两个角色同时动作时给一个同步的视觉节拍（比如同时的粒子脉冲）。**为什么**：强化"镜像联动"这个核心机制的感知。

**这条最值得先做**：左右形状冗余。这是唯一一条"不做就是排他"的问题。

### 3.6 09 星穹拓荒 · Stellar Frontier

**现状**
程序生成星系殖民 Roguelike，一局一宇宙，永久死亡 + 遗产成长。有四种模式（星图长征/深空漫游/每周挑战/沙盒）、九站跃迁、科技树、防御工事、陨石与星兽。本轮修掉了三个把玩家"冻住"的问题：**首次进入弹出的操作说明在小屏上按钮被裁掉、Esc 又关不掉，导致对局永久暂停**（这直接造成了"不能移动、人傻站"）；**教学面板被 CSS 在所有手机上强制隐藏**；**教学只在星图长征模式里开**。此外还修了我上一轮美术改动引入的布局事故（`.glass{position:relative}` 覆盖了 8 个元素的绝对定位）。

**主要问题**
1. **教学结束后的目标真空**：教程是 6 步（降落→采矿场→50 矿石→聚变发电机→居住舱→抵御事件），走完后玩家进入"开放但无引导"的状态。
2. **电力/覆盖范围不可视**：能源赤字是核心压力来源，但玩家看不出"哪条线过载、哪栋楼没电"。
3. **里程碑存档"30 秒销毁"的提示不够醒目**（README 里提到"读取后30秒销毁"）。这个规则比较特殊，玩家一旦没看见就可能失去进度。
4. **事件密度在后期可能失控**：威胁等级越高事件越频繁，缺少"喘口气"的节奏控制。
5. **移动端单指拖动与建造点击存在冲突风险**（拖动视角 vs 点击放置）。

**优化建议**

- **P1｜教程后接"软目标"链**：教学结束后自动接一段非强制的建议目标（"建议：把电力转正""建议：造 1 座炮塔对抗第 3 站"），完成后淡出。**为什么**：把"教学结束"到"我能自己玩"之间的空档补上。
- **P1｜电力与覆盖可视化**：点选建筑时高亮它的供电链与覆盖半径；顶栏电量条在赤字时标出"哪几栋在吃电"。**为什么**：能源是这款游戏的命脉，看不见就等于不可控。
- **P1｜存档规则显著化**：进入对局时用一次性横幅明确"本局为里程碑存档，读取后 30 秒销毁"，并在存档按钮上标倒计时。**为什么**：特殊规则必须显著，否则就是陷阱。
- **P2｜事件节奏阀门**：连续两次负面事件后强制插入一次喘息期（或降低下一次事件强度）。**为什么**：永久死亡 + 事件连击 = 挫败感堆积。
- **P2｜多档位与"快速重开"**：不同难度/种子各留一档，并在结算页提供"用同一种子重开"。**为什么**：Roguelike 的乐趣在重试，重试成本要低。
- **P2｜移动端建造独立按钮**：把"拖动视角"和"放置建筑"分配到不同手势（例如放置时锁定视角）。**为什么**：消除误操作。
- **P2｜遗产商店的引导**：首次进入档案页时用一句话说明"死亡不是结束"。**为什么**：这是这款游戏最重要的心理设计，藏起来太可惜。

**这条最值得先做**：教程后的软目标链。它把一个"开放世界式的空档"变成"有方向的推进"，对留存的影响最直接。

## 四、横向共性问题（十款都有，改一处收益十次）

逐款建议之外，有几类问题在十款游戏里反复出现。它们比单款优化更值得优先处理，因为**一次规范能同时改善十款**。

### 4.1 新手引导：需要一套统一规范

本轮给《深渊词条》《幻境争锋》《镜像迷城》补了引导，修好了《星穹拓荒》的引导，但《余烬之城》《时间碎片》《情绪花园》的引导仍是"读文档"式的。更重要的是，**现有引导的实现方式彼此独立**——每款各写一套浮层、各用一套 localStorage key。建议抽出统一规范（不一定要抽公共代码，但要有统一契约）：

| 契约项 | 要求 | 理由 |
|---|---|---|
| 触发 | 首次进入自动触发，落一个 `*_tut_v1` 标记 | 老玩家不该被打扰 |
| 跳过 | 必须有一眼可见的「跳过」，且 Esc 也能退出 | 被引导卡住比不引导更糟 |
| 重看 | 菜单/设置里必须能重看 | 玩家常常跳过之后才后悔 |
| 不阻塞 | 引导期间的覆盖层设 `pointer-events:none`，只有按钮吃事件 | 本轮的引导都做到了，应固化为规范 |
| 步数 | 5~9 步，每步只教一件事，尽量用"做一次"而不是"读一段" | 超过 9 步的引导完成率会陡降 |
| 判定 | 能自动判定的就自动推进（买到英雄→下一步） | 减少点击负担 |

**反例参考**：《星穹拓荒》原本的做法是"弹一整页六段操作说明 + 暂停世界"。本轮虽然把它修得关得掉了，但**"一次性读完一页表格"本身就是最弱的引导形态**。同类问题在《星火拓荒》也存在（6 页页签说明）。建议长期都把这类大文档降级为"随时可查的手册"，而把首次体验交给分步引导。

### 4.2 移动端：多款游戏在手机上等于不可用

这是**整个合集最大的系统性缺口**。逐款盘一下输入方式：

| 游戏 | 手机可用性 | 问题 |
|---|---|---|
| 02 星火拓荒 | 严重受限 | 建造依赖右键菜单/左键放置，手机没有右键 |
| 04 深渊词条 | 不可用 | 键盘 WASD + 鼠标开火 |
| 05 幻境争锋 | 可用但精度差 | 拖拽放子在窄屏上容易放错 |
| 07 镜像迷城 | 基本可用 | 虚拟摇杆需要手感调校 |
| 08 时间碎片 | 布局风险 | 三栏并排在窄屏上会挤压 |
| 09 星穹拓荒 | 可用 | 拖动视角与放置建筑的手势冲突 |
| 06 回声 Echo | 可用 | 本就以"点按屏幕"为主 |
| 03 拓城记 | 可用 | 网格点击精度 |

建议按这个顺序处理：**先给 04 和 02 加触控方案**（这两款手机上完全不能玩），再统一调校其余几款的手感。具体做法上，最小可行方案是"左下虚拟摇杆 + 右下动作按钮"，而不是重写输入层——各款的输入都集中在少数几处（例如 `main.js` 的 `bindInput`），改造成本可控。

### 4.3 存档：单档 + 清缓存即丢，是长期陪伴的硬伤

现状是每款一个 localStorage key、单存档位。带来三个问题：

1. **误操作无退路**：模拟经营和剧情游戏尤其需要"回退一步"。
2. **清缓存即清进度**：浏览器清理缓存、换设备、换浏览器都会丢。而《时间碎片》有 102 关、《拓城记》有 11 个里程碑——丢失成本很高。
3. **无法迁移**：玩家换手机就重来。

建议分两步：
- **P1｜存档导出/导入**：把存档序列化成一段文本或二维码，玩家可以自己保存。**为什么**：这几乎零成本（不需要服务器），却能一次性解决迁移和备份问题。实现上各款的存档已经是 JSON，加一个复制/粘贴入口即可。
- **P1｜关键游戏加"自动存档时间线"**：保留最近 5~10 次自动存档，可回退。**为什么**：比多档位更省玩家心智，也更有效防误操作。

### 4.4 可访问性：现在只有零星考虑

十款里我明确看到无障碍相关设计的是《镜像迷城》（色盲考虑在本轮被点出）和《回声》（声纹可视化）。其余几款普遍缺少：

- **色盲冗余**：《拓城记》的季节色、《情绪花园》的情绪色、《幻境争锋》的羁绊色都只靠颜色区分。建议凡是"只用颜色区分信息"的地方，都补一个形状/图案/文字冗余。
- **字号与对比度**：《星穹拓荒》有字号档位（`body.fs1/fs2`）值得推广；其余几款的正文在手机上都偏小。
- **纯键盘可玩**：剧情类（01）与解谜类（07、08）应做到全键盘可操作。
- **动效敏感**：多款有粒子、屏震、闪烁（04 的受击闪白、05 的战斗特效）。建议提供"减少动效"开关——这不是小众需求，部分玩家会因闪烁不适。
- **静音可玩**：《回声》是极端例子，但《情绪花园》的音乐模式也依赖听觉。

### 4.5 代码组织：大文件正在变成风险

实测当前体积：`3/js/render.js` 105.9KB、`4/js/game.js` 136.2KB、`8/js/ui.js` 89.5KB、`5/index.html` 149.3KB、`1/余烬之城.html` 172.6KB。这个体量本身不是错（无构建工具的前提下，少文件反而简单），但带来两个具体风险：

1. **改一处怕碰别处**：本轮就真实发生过两次——子任务用 PowerShell 批量替换把三个文件的中文编码弄坏了；我上一轮给 `.glass` 加 `position:relative` 覆盖了 8 个元素的绝对定位，直到量元素坐标才发现。
2. **缺回归测试**：目前只有《时间碎片》（442 项）和《镜像迷城》（关卡校验器）有自动化测试。

建议：
- **P1｜给"表现层改动"加一个通用布局体检**：本轮我做的 `diag-layout-health.js` 就是雏形——扫描所有定位元素是否跑出视口。它可以变成十款通用的冒烟测试。
- **P1｜把"隐形遮罩抢点击""调用了不存在的方法"两类静态检查固化**：本轮靠这两个检查抓出了《回声》的两个致命 bug（隐藏菜单挡住启动页、`this.initFX is not a function`）。它们都是几十行脚本，值得每款都跑。
- **P2｜给大文件加注释分区表头**：`render.js` / `game.js` 这类文件在顶部列一个"函数索引"，能显著降低阅读成本。

### 4.6 小噪音：favicon 404

十款游戏在浏览器控制台都会报一条 `favicon.ico 404`。功能上无影响，但它有两个实际代价：一是每次排查问题时都要先排除它，二是控制台第一眼就是红色错误会让玩家以为游戏坏了。**建议统一加一组内联 SVG favicon**（几行代码，不用外部文件），顺手也能让浏览器标签页更易辨认。

十款游戏的**技术底座（零依赖、零素材、离线可玩）是整个项目最值钱的资产**，美术也已经在上一轮补到了不错的水平。现在真正的短板集中在三处：**新手引导不统一、移动端基本不可用、存档太脆**。这三件事都不需要重写游戏，做完之后这十款才真正具备"发给任何人、任何设备都能玩下去"的完整度。
